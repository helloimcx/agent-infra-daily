## 今日核心判断

Agent 工程的稀缺资源正在从代码生成转向可独立验证的正确性。对百万用户平台，验证控制面应独立于生成与执行控制面；不能以 Agent 自己修改后的测试通过率代替生产一致性。

## 重大进展与证据边界

**P0：Anthropic 披露 Messages API 从 Python 迁移至 Rust 的生产实践。** 官方文章标注 2026-11-25，未给出精确时区和发布时间，因此只能确认日期级近期信号，不能严格断定落在北京时间过去24小时内。迁移本身已于9月进行，并非今天上线。厂商报告每请求 CPU 下降约70%，首 token 延迟中位数下降约20%。这些是该服务的自报结果，不是通用语言或 Agent 框架 benchmark。

关键机制是让旧服务成为行为参照，模型只运行一次，候选实现复用输出；分阶段比较输入和输出，利用不含原始客户文本的差异指纹归类问题。修复 Agent 在隔离环境中重现差异，人工审核后再以真实流量验证。原文还指出测试迁移可能弱化断言。由此推论：验证器必须有独立的变更权限与版本生命周期，旧实现也不能被视为永远正确的规范。

本次有限独立检索未确认其他同等级新增，不凑数。

## 架构路线与 Tradeoff

历史对照：Google 11月20日介绍跨云 Agent Anomaly Detection，明确仍是 Private Preview。其分析依赖符合约定的遥测数据，不要求接管执行环境；因此适合观察跨步骤行为，但不能代替同步授权。传输提示词和回复还涉及数据驻留、脱敏与租户授权。Anthropic 的生产差异验证侧重版本等价性，Google 的行为观测侧重会话风险；两者都不能单独证明工具副作用安全。

自建验证控制面便于保留数据边界和自定义不变量，但需要承担采样、存储、比较器维护与误报处理；托管观测降低接入成本，却引入数据出口与供应商依赖。建议高风险操作同步拦截，低风险诊断异步执行。

## 标准与研究

本次未确认新的 MCP/A2A 正式标准。Google 示例采用 OpenTelemetry 实验性 GenAI 语义约定；这不是跨厂商执行授权标准。应对遥测 schema 做版本管理，不把实验字段当作稳定协议。

## 百万用户 Cloud Agent 工程建议

建立 Verification Plane：生产事件流 -> 脱敏采样 -> 确定性重放 -> 差异归类 -> 隔离修复 -> 人工审批 -> 灰度验证。将模型响应、工具回执和策略版本作为重放输入；影子执行禁止真实外部写入、重复计费和重复发送通知。按租户风险分层采样，保留最少必要信息；对授权、账单、文件写入等不变量采用独立维护的测试。对模型非确定性使用固定录制输出，不以自然语言逐字一致性评价任务质量。

建议先在 Gateway 协议转换、流式事件解析、Checkpoint schema 升级三处试点。指标包括按流量加权的差异率、关键不变量违规率、修复回归率、验证成本及灰度回滚时间；阈值由自身基线确定，不引用厂商数字作为 SLO。
